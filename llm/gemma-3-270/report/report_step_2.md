# 🚀 Gemma-3-270M LoRA 파인튜닝 2차 실험 리포트

본 실험은 1차 실험의 한계를 극복하기 위해 데이터셋 규모를 확장하고 학습 횟수(Epoch)를 늘려, 모델의 정형 데이터(JSON) 추출 능력을 고도화하는 데 목적을 두었습니다.

---

## 1. 실험 환경 및 변경 사항 (Environment & Setup)
* **Base Model**: `google/gemma-3-270m-it` (On-Device 최적화 모델)
* **Dataset Size**: **240개** (기존 대비 140% 증가)
* **Epochs**: **10회** (기존 3회 대비 3.3배 증가)
* **Hardware**: Local CPU Environment

---

## 2. 학습 지표 추이 (Training Progress)
학습이 진행됨에 따라 모든 지표가 우상향하며 모델이 데이터에 최적화되는 양상을 보였습니다.

| 지표 (Metric) | 2 Epoch (초기) | 10 Epoch (최종) | 변화 양상 |
| :--- | :--- | :--- | :--- |
| **Loss (손실)** | 3.681 | **1.7516** | **-52.4% 감소 (긍정적)** |
| **Token Accuracy** | 51.55% | **69.36%** | **+17.81%p 상승 (긍정적)** |
| **Entropy** | 1.536 | 1.823 | 답변의 다양성 유지 |

> **[분석]** 최종 손실값(1.75)과 정확도(69.3%)는 1차 실험(Loss 3.5 / Acc 52%)에 비해 **비약적으로 발전**했습니다. 모델이 학습 데이터의 패턴을 훨씬 더 명확하게 파악하기 시작했음을 의미합니다.

---

## 3. 결과 검증 및 트러블슈팅 (Validation & Issue)
검증 과정에서 예상치 못한 `null` 출력 문제가 발생했습니다.

* **Input**: "모레 저녁에 판교 카카오 본사에서 미팅 있음"
* **Output**: `null`
* **현상 분석**:
    1. **Overfitting 가능성**: 특정 형식(JSON)을 학습하는 과정에서 출력 조건이 맞지 않으면 아예 출력을 포기하거나, 잘못된 토큰(EOT)을 먼저 생성함.
    2. **Post-processing 오류**: 모델이 생성한 원문 텍스트가 불완전하여 파이썬 코드 내 `json.loads()` 과정에서 파싱 실패로 인해 `null`을 반환했을 가능성.
    3. **Stop Token 문제**: 학습 시 사용된 EOS(End Of Sentence) 토큰이 추론 시 너무 일찍 트리거되어 내용 생성 전에 종료됨.

---

## 4. 향후 개선 방향 및 기술적 근거

### 🛠️ 검증 코드 보정 (Python Type Hinting 적용)
`null` 발생 원인을 파악하기 위해 생성된 원문(Raw Text)을 먼저 확인하도록 코드를 수정해야 합니다.

원리: Gemma-3-270M은 파라미터가 적어 추론 시 유연성이 부족합니다.
max_new_tokens 설정이나 temperature 설정을 조정하여 출력을 유도해야 합니다.
