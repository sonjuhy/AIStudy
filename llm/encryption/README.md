# 동형암호 실험

## 목적

동형암호(HE)로 LLM 연산을 실제로 암호화된 상태에서 수행하는 것이 **가능한지 / 어디까지 적용 가능한지**를 학습 목적으로 검증한다.

## 사전 준비

- 테스트 모델: SmolLM 135M
- 모델 가중치만 가져오고 코드는 동일하게 재작성 (추후 수정 및 실험할 수 있게)
- HE 라이브러리/스킴 확정: 실수 가중치를 다뤄야 하므로 **CKKS** 기반, 라이브러리는 진입장벽이 낮은 **TenSEAL**(MS SEAL 래퍼)로 시작. 필요 시 OpenFHE 등으로 확장

## 진행 순서

### 1단계 — 재작성 모델의 평문 검증

- 재작성한 코드가 원본 SmolLM 135M과 **암호화 없이(평문)** 동일한 출력을 내는지 먼저 확인
- 이 단계를 건너뛰면 이후 HE 적용 후 오차가 발생했을 때, 원인이 HE 근사 오차인지 재작성 버그인지 구분할 수 없음

### 2단계 — 선형 연산(matmul 등)부터 HE 적용

- softmax, 활성화 함수(GELU/SiLU 등), LayerNorm/RMSNorm의 rsqrt·분산 계산 등 비지원(비다항) 연산은 제외하고, HE가 원래 잘 지원하는 선형 연산(행렬곱, 덧셈)부터 암호화 상태로 테스트
- 비교 기준은 **완전히 동일한지가 아니라 오차 크기**로 판정 (CKKS는 근사 암호화라 비트 단위로 절대 같아지지 않음)
  - 예: cosine similarity, relative error 등 기록
  - HE 파라미터(poly modulus degree, scale 등)를 바꿔가며 오차가 어떻게 변하는지도 함께 관찰

### 3단계 — 곱셈 깊이(multiplicative depth) 한계 관찰

- 트랜스포머 레이어 수를 하나씩 늘려가며 몇 개 레이어까지 노이즈 누적 없이 버티는지 확인
- 한계에 도달하면 bootstrapping 필요 여부 및 비용(속도 저하 정도)을 기록
- "LLM에 HE를 적용하는 게 가능한가"에 대한 핵심 답이 이 단계에서 나옴

### 4단계 — 비지원 연산의 클라이언트-서버 하이브리드 확장

- softmax, 활성화 함수 등 비다항 연산은 비밀키를 가진 클라이언트가 복호화 → 평문 계산 → 재암호화하는 방식으로 처리
- 진행 전에 **위협 모델을 명시**: 비밀키는 클라이언트가 보유, 서버는 암호문 위에서 선형 연산만 수행하며 평문 데이터를 볼 수 없음이 이 실험이 보여주고자 하는 보안 속성임을 문서화
- 레이어마다 발생하는 암/복호화 왕복 비용(레이턴시, 통신량)도 함께 측정

## 시각화

위 과정을 가능하다면 시각화를 통해 눈으로 직접 확인할 수 있도록 함 (레이어별 오차 추이, 곱셈 깊이 대비 정확도, 단계별 소요 시간 등)
